## 口頭報告架構與講稿 (對應評分：技術內容完整、表達清晰充分)

以下為您設計的口頭報告講稿，時間預計掌握在 5 至 8 分鐘，邏輯依循「發現問題 $\rightarrow$ 核心技術手段 $\rightarrow$ 達成功效」的專利思維推演。

**【開場與發明想法】**
「大家好，我今天要發表的專利題目是『一種具備加密傳輸與身分驗證之Linux預啟動測試機系統及方法』。
這個發明的動機，來自於企業在自動化裝機與測試環境中面臨的資安漏洞。我們在期中報告探討了中華民國專利 TW I864470 B，該前案成功將預啟動伺服器 (PXE) 部署到 Linux 系統上，解決了 Windows 系統本身安全性較低的問題。然而，我進一步檢視後發現，該前案在『傳輸過程』中仍存在嚴重的資安死角。」

**【先前技術缺失】**
「最接近的先前技術主要有兩個致命缺失：
第一，**傳輸未加密**：前案使用 TFTP (簡單檔案傳輸協定) 來下載預啟動程式，這是明文傳輸，駭客很容易在區域網路內透過中間人攻擊 (MITM) 側錄或竄改映像檔。
第二，**缺乏設備身分驗證**：伺服器端只要收到 DHCP 與 TFTP 請求就會配發檔案，完全無法確認這台發出請求的『測試機』是不是公司內部合法授權的設備，這會導致企業機密測試系統外洩。」

**【本發明技術手段與解決問題】**
「為了解決上述問題，本發明引入了『零信任架構』的技術手段。
我們的核心技術特徵在於：測試機電腦在取得 IP 後，必須先向『驗證伺服器』發送基於其硬體信任根（例如內建的 TPM 晶片）所生成的『身分憑證』。
當驗證伺服器確認這台設備是合法授權的測試機後，才會核發一組『短期加密存取權杖 (Token)』。接著，測試機利用 UEFI HTTP Boot 功能，透過 HTTPS 超文本傳輸安全協定，並將權杖夾帶在標頭中，向預啟動伺服器發起下載請求。伺服器驗證權杖無誤後，才會透過 TLS 加密通道將映像檔傳輸給測試機。」

**【達成功效與總結】**
「透過這樣的技術手段，本發明達成了『端到端加密』與『硬體級設備鑑別』的雙重功效。不僅解決了預啟動映像檔在傳輸過程中可能被竊聽的風險，更從根本上阻絕了未經授權的非法設備連入測試網路，大幅提升了自動化部署的資訊安全等級。以上是我的報告，謝謝大家。」

## 專利知識及問題回應 (Q&A 防禦準備) (對應評分：對專利知識及問題的回應)

**Q1：你的發明中，哪些是「特別技術特徵」，哪些是「一般技術特徵」？**

* **回答策略：** 「本案的『一般技術特徵』包含了測試機電腦、網路環境、動態主機設定伺服器 (DHCP) 以及預啟動程式伺服器，這些是維持網路開機運作的基礎構件。而本案的『特別技術特徵』則是**驗證伺服器的身分憑證核對機制 (TPM)**、**存取權杖 (Token) 的發放與驗證**，以及**基於 HTTPS 的加密檔案傳輸協定**。這些特別技術特徵正是為了解決前案 TFTP 明文傳輸缺失所不可或缺的核心手段。」

**Q2：這個發明只是把 HTTPs 和 TPM 應用在網路開機上，這樣有具備「進步性」嗎？是不是簡單變更？**

* **回答策略：** 「這並非簡單變更。雖然 HTTPS 和 TPM 都是現有技術，但在傳統的 PXE 網路開機環境中，因為測試機尚未載入作業系統，通常只能依賴最基本的網卡廣播與 TFTP 傳輸。本發明將 UEFI HTTP Boot 結合硬體信任根，克服了『無作業系統狀態下無法進行強認證』的技術困難。這產生了『有別於先前技術之功效』，也就是在裝機前就實現零信任網路架構，這對通常知識者來說，並非單純將技術拼湊就能輕易完成的，因此具備進步性。」

**Q3：這是一個軟體專利，請問它符合「發明適格性 (利用自然法則之技術思想)」嗎？會不會落入單純的人為規則或商業模式？**

* **回答策略：** 「本案絕對符合軟體專利的適格性。我們並非單純提出一個資訊安全的人為管理規則，而是將資安管控『具體實現』於資訊硬體資源上。本方法必須藉由『動態主機設定伺服器』、『驗證伺服器』與『測試機內部的 TPM 晶片』進行實體網路封包的協同運作，對『技術性質的資料（身分憑證與加密權杖）』進行運算與傳輸控制。因此，它是結合硬體資源與資訊自動化技術的具體技術手段，完全符合發明定義。」
